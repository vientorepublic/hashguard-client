# AGENTS.md — hashguard-client

Official TS/JS client SDK for the Hashguard PoW CAPTCHA service. Works in Node/Bun/Deno/browser. Full API/usage: `README.md`. This repo has **no CI workflow** and is **not published by any CI** — publishing is manual.

## Commands

- `npm run build` = `build:wasm` → `tsc` → `build-esm` (esbuild dual ESM+CJS). **The WASM step needs a Rust toolchain:** `rustup target add wasm32-unknown-unknown` and `cargo install wasm-pack`, or `npm run build:wasm` fails.
- `npm test` (jest + ts-jest, node env), `npm run type-check` (`tsc --noEmit`), `npm run lint` (eslint `--fix`), `npm run format:check` (prettier).
- **E2E:** `npm run test:e2e` builds then runs a real WASM solve against `dist/index.mjs` — needs the Rust toolchain above.
- `prepublishOnly` runs type-check → lint → format:check → test → build. Publish manually with `npm run publish:patch|minor|major` (no git tag created).

## WASM / generated code

- **WASM is not auto-initialized.** The SDK falls back to pure-TypeScript unless the caller does `await initHashGuardWasm()` once at startup. `isWasmReady()` reports the active path.
- `src/wasm-pkg/` is generated by `build:wasm`: `wasm_binary.ts|js` and `hashguard_wasm.js` are **AUTO-GENERATED (do not edit)**. They are gitignored — only `*.d.ts` stubs are tracked. Don't treat their absence as a bug; regenerate with `npm run build:wasm`.
- The Rust crate is in `crate/` (`cdylib`, wasm-bindgen + sha2/hex/js-sys; release profile `opt-level=z`, `lto`, `codegen-units=1`, `wasm-opt -Oz`).

## Structure

- Entry: `src/index.ts` re-exports the public surface. Core files: `client.ts` (`HashGuardClient`), `solver.ts` (`solvePow`), `crypto.ts` (`sha256hex`/`verifyProof`), `token-validator.ts`, `token-cache.ts`, `resource-guard.ts` (`ResourceGuard`), `wasm-loader.ts`, `types.ts`.
- `tsconfig.json`: `emitDeclarationOnly` (types only, no JS), `module: esnext`, `target: ES2020`; `package.json` is `"type": "module"`.

## API / behavior gotchas

- `internal request` on the client is **private** — you cannot override HTTP via subclassing. Use the `headers` option, or set a custom global `fetch` before constructing the client.
- `execute()` requires a server exposing `POST /v1/pow/assessments` (there is no fallback that bypasses assessment on error). The result type is `PowFlowResult` — narrow on `challengeRequired` before reading solve stats.
- `introspectToken` / `ResourceGuard.checkAccess` default to `consume=true` (single-use). Local/stateless signature validation cannot enforce single-use — use `introspectToken` on the backend for authoritative checks.
- Test/integration server: `https://hashguard.viento.me`. `scripts/test-server-integration.mjs` is a manual integration test against a running server at `http://localhost:3000` (not wired into npm scripts).
